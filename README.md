# Device Check

Веб-сервис диагностики оборудования компьютера. Показывает конфигурацию ПК прямо в браузере и для каждого параметра указывает **источник** и **степень достоверности**.

- Сайт: https://device-check.umolab.ru. Windows Agent скачивается на странице [/agent](https://device-check.umolab.ru/agent).
- CI/CD, автодеплой и выпуск релизов описаны в [deploy/README.md](deploy/README.md).

**Текущий статус:**
- сайт — браузерный режим (этап 1) и показ полного отчёта Windows Agent;
- агент — сборщик, JSON, трей-приложение и локальный API ([agent/README.md](agent/README.md)).

## Структура репозитория

```
device-check/
├── web/        Nuxt 3 + TypeScript — фронтенд (этап 1)
├── api/        Laravel + MariaDB — появится на этапе 5 (публичные отчёты)
└── agent/      C# / .NET 10 Windows Agent — этап 1 агента готов (консольный сборщик + JSON), см. agent/README.md
```

### agent/

Портативный Windows-сборщик: WMI/CIM, SMBIOS, CPUID, DXGI/D3D12, QueryDisplayConfig + EDID. Выдаёт тот же HardwareReport v1.0 с `scan.source = "agent"`. Права администратора не нужны. Работает в трее: меню открывает этот сайт ссылкой `/#agent=<порт>&token=<токен>`, и дашборд забирает полный отчёт через локальный API на `127.0.0.1` (плагин `plugins/agent.client.ts`, клиент `lib/agent.ts`). Подробности, команды сборки portable ZIP и список неопределяемых параметров — в [agent/README.md](agent/README.md).

### web/

```
lib/                 логика без привязки к Vue (тестируется отдельно)
  types.ts           схема HardwareReport и Field<T>
  field.ts           конструкторы полей (field / unavailable / agentOnly)
  parse.ts           чистые парсеры: ОС, браузер, архитектура, строка WebGL-рендерера, частота обновления
  collectors/        сбор данных через браузерные API (по одному модулю на раздел)
  report.ts          полнота диагностики, производные значения, текстовый отчёт
  format.ts          форматирование значений (единицы, байты, даты)
  sections.ts        какие поля и в каком формате показывать в каждом разделе
composables/         состояние сканирования, локальные отчёты, i18n, копирование
components/          UI: FieldRow, ConfidenceBadge, MemorySlots (SVG), OverviewGrid, ScanBar…
pages/               / (dashboard), /about, /limitations, /privacy
i18n/                ru.ts, en.ts
tests/               unit-тесты (vitest)
```

Слои разделены: **сбор → нормализация → хранение → отображение**. Если один сборщик падает, его шаг помечается ошибкой, раздел заполняется полями `unavailable` с причиной `error`, а сканирование продолжается.

## Запуск

Требуется Node.js ≥ 20 (проверено на 21.6).

```bash
cd web
npm install
npm run dev        # http://localhost:3000
npm test           # unit-тесты
npm run typecheck  # vue-tsc
npm run build && node .output/server/index.mjs   # продакшен (SSR)
```

> `nuxi` зафиксирован на версии 3.14.0: более новые версии требуют Node ≥ 21.7.

## Формат данных

Каждый параметр — это `Field<T>`:

```jsonc
{
  "value": 16,
  "source": "navigator.hardwareConcurrency",
  "confidence": "exact",          // exact | approximate | detected | unavailable
  "collected_at": "2026-11-10T12:00:00.000Z",
  "note": "threads_limit",        // необязательная оговорка (код i18n)
  "reason": "agent_required"      // только для unavailable: почему нет данных
}
```

Корень отчёта: `schema_version`, `scan` (`id`, `created_at`, `source: browser|agent`, `platform`, `collector`), `system`, `cpu`, `motherboard`, `memory` (с `modules[]`), `gpu[]`, `storage[]`, `volumes[]`, `displays[]`, `browser`, `limitations[]`. Полное описание — в [web/lib/types.ts](web/lib/types.ts). Схема не привязана к Windows; формальная валидация и импорт запланированы на этап 2.

## Что умеет браузерный режим

| Раздел | Получаем | Достоверность |
|---|---|---|
| CPU | логические потоки, архитектура | exact |
| Memory | объём (`navigator.deviceMemory`, округлён и ограничен сверху) | approximate |
| GPU | производитель/архитектура (WebGPU), модель и PCI ID (строка WebGL), тип адаптера (эвристика), поддерживаемые API | exact / detected |
| Display | разрешение (CSS и физическое), DPR, частота обновления (измеряется), HDR, цветовой охват, глубина цвета, несколько дисплеев | exact / detected / approximate |
| System | ОС и версия (UA Client Hints, иначе User-Agent), браузер, тип устройства, язык, часовой пояс | exact / detected |
| Browser | WebGL/WebGPU, квота хранилища, сеть, батарея, точки касания | разная |

Материнская плата, модули RAM, накопители, разделы, модель монитора, видеопамять и драйверы браузеру **недоступны** и показываются как `unavailable` с причиной — никаких догадок. Эти данные даёт Windows Agent.

## Режим Windows Agent

`DeviceCheck.Agent.exe` работает в трее. Пункт меню «Открыть Device Check» (или левый клик по значку) открывает сайт ссылкой `/#agent=<порт>&token=<токен>`. Дальше по шагам:

1. Плагин `plugins/agent.client.ts` читает фрагмент и сразу убирает его из адресной строки. Токен остаётся только в `sessionStorage` этой вкладки.
2. Сайт проверяет `GET http://127.0.0.1:<порт>/api/status`.
3. Затем забирает отчёт: `GET /api/report/{id}`, а если отчёта ещё нет — сначала `POST /api/scan`.
4. Дашборд переключается в режим «Windows Agent» с 7 категориями. Кнопка повторного скана идёт через агента.
5. Если агент закрыт или перезапущен (новый токен), сайт возвращается в браузерный режим.

Отчёт агента — тот же HardwareReport v1.0. Он дополнительно содержит `memory.smbios_slots`, по которому слоты рисуются вместе с пустыми и распаянными, и `diagnostics` (статусы сборщиков). Поля, которые бывают только в браузере (`css_resolution`, `pixel_ratio`, `browser_name`…), в нём отсутствуют, и интерфейс их просто не показывает.

## Приватность

- Сканирование выполняется локально, на сервер ничего не отправляется.
- Имя компьютера и серийные номера не собираются.
- «Сохранить локально» пишет в `localStorage` (до 10 отчётов), их можно удалить.
- Язык хранится в cookie `dc_locale`. Аналитики и сторонних шрифтов/скриптов нет.

## Тестирование этапа 1

- 24 unit-теста (парсеры, поля, форматирование, производные значения, разбор ссылки агента) — проходят.
- `vue-tsc` — без ошибок.
- SSR: все страницы отдают 200, есть `<title>`, Open Graph, корректный `lang`; неизвестный путь — 404.
- Локализация: `Accept-Language`, cookie, `?lang=en|ru`.
- E2E в headless **Chrome 156** и **Edge 157** (Windows 11, AMD Radeon 780M): сканирование проходит все 6 шагов, ошибок в консоли нет, локальное сохранение работает, горизонтального переполнения нет на ширине 1366 и 375 px.
- Режим агента: настоящий локальный API агента и сайт в headless Chrome, 1366 и 375 px, RU и EN. Подключение по ссылке, 7 шагов, повторный скан, слоты SMBIOS — без ошибок в консоли, без непереведённых ключей, без горизонтального переполнения.
- **Firefox не проверялся** — на тестовой машине он не установлен.

## Известные ограничения

- Firefox и Safari не проверены вручную; по документации в них не будет Client Hints и `deviceMemory`, а модель GPU будет обобщена или скрыта (это обрабатывается: такие поля помечаются соответствующим статусом).
- Видна только активная видеокарта и только текущий экран.
- Частота обновления измеряется по `requestAnimationFrame` и может быть занижена в фоновой вкладке или в режиме энергосбережения.
- Локаль переключается через cookie/`?lang=`; отдельных URL по языкам (`/en/…`) для SEO пока нет.
- Импорт JSON, публичные ссылки и бэкенд (Laravel/MariaDB) — следующие этапы. Кнопка «Публичная ссылка» неактивна.
- Связка сайт ↔ агент проверена только для локального сайта. Если сайт на публичном домене, Chrome спросит у пользователя разрешение на доступ к локальной сети; это не проверялось.
